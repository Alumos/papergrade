# Papergrade v0.2.0：原生 Ollama 入库与固定学号双联卡

## 本版流程

PDF 上传 → 保留原件 → 手机/电脑浏览器 PDF.js 按页转 JPEG → VPS 流式接收页证据 → 独立 Worker 逐页调用后台配置的 Ollama → 保存 Markdown/LaTeX 与进度 → OpenAI-compatible 文本模型抽取题型/分值/题号 → 教师显式采纳并补齐答案 → 发布冻结 a5-v2 → 一张 A4 上下两份答题卡 → 裁开后手机浏览器 OMR → Go 独立复核学号与填涂 → 确认入库与统计。

整个过程不在 VPS 部署 OCR/LLM，也不在 VPS 安装 PDF 渲染器。浏览器转换期间须保持页面前台；中断后重新选取同一原 PDF，可跳过已准备页，服务端拒绝不同字节覆盖已准备证据。最多30页，逐页2048长边/4MiB/8MP，OCR结果合并上限120KB；大于限制应拆卷，不能无限积压。

## 后台如何填模型

### OCR

设置 → 模型与服务设置 → OCR：

- 类型：Ollama 原生。
- 地址：你自己的 Ollama HTTPS 基址（可用 DDNS 自定义端口），**默认空，不预置任何 NAS 地址**。不要附加 /api/chat。
- 模型：填写NAS实际安装的完整名字，例如 longwayxu/xiaomi-ocr-0:bf16。
- API Key：Ollama 原生本地服务通常没有，可以留空；若 HTTPS 反代增加 Bearer 鉴权，则填反代要求的密钥。Basic Auth、自定义请求头尚未实现，不能把账号密码塞进URL。
- 保存后 API/Worker 下一次调用使用最新配置，无需重启。

公网DDNS请务必使用正确证书的HTTPS，并在反代加鉴权/IP限制；HTTPS并不是授权机制。不应直接把11434暴露公网。私有局域网/CGNAT VPN literal IP允许Ollama HTTP；公网HTTP禁止，普通域名需HTTPS。

测试按钮仅验证 Ollama 的模型/版本相关可达性，不代表图片识别或特定模型加载已通过。请求图片使用 /api/chat、stream:false、think:false、官方文档转录提示词；公式输出LaTeX，表格可能OTSL。每页总超时300秒，队列租约360秒，不自动盲重推理；失败记录页码，人工点重试只补失败页。

### AI

AI Base URL填OpenAI-compatible基址（通常含/v1），模型填供应商实际ID，密钥在后台输入并AES-GCM加密保存。需要Chat Completions、response_format json_object、temperature、max_tokens支持。系统发OCR文本给AI，不能让模型猜原卷缺失答案/分值；教师发布前必须补齐。

本版只实测了协议fixture和用户授权的Ollama；未提供真实付费大模型密钥，**不宣称真实付费AI供应商已联通验收**。

## 固定答题卡

- 物理单卡210×148.5mm（严格半张A4），双联整页210×297mm，不缩放旧A4模板。
- 上下两卡分别有四角4mm定位块、方向/黑白参考、学号十进制填涂矩阵与最多40题（每题2–5选项）；涂点直径3.6mm。
- 名册学号必须纯ASCII数字、统一1–12位；作为字符串保留前导零，绝不自动补零或猜学号。发布后位数冻结。
- 学号每列0–9只填一个，2B涂满；题目可单选、多选、判断。空白、轻涂、擦除、多涂、不确定分开处理。
- 二维码只标识同一考试/发布版本，全班相同，**不包含学生身份、不用于学生身份辅助验证**。身份只来自学号OMR；码不可读仍可按已选考试的清晰学号识别，读出不同考试码则进异常。
- 字母印在涂点之外，小字需真实打印验收。按A4/100%/关闭页眉页脚打印，先裁中线，再逐张扫单卡；整张双联混扫会被拒绝。
- 输出可直接下载SVG或实际A4 PDF。PDF由浏览器将固定SVG以300dpi渲染后嵌入，保留中文、不依赖服务器字体；不是界面截图。下载可能按每对学生一页操作，批量纸打印可自动成对。



## 英语教师答题卡（a5-v4）

英语试卷用专用的半A4双联卡，和 a5-v2 同尺寸、不同版式，发布后一起冻结。**版式完全由这份卷子真实的题型题数决定**，外观风格统一：

- **一题一行、横着排**：左边题号，右边依次是 A/B/C… 的填涂格。
- 填涂格是**横向长方形**（4.6×3.4mm），字母印在格子里，2B 涂满整格。
- 列数按实际题目自动计算：60 题 7 选项排 4 列 × 15 行；只有 15 题就排 6 列 × 3 行，不会留半张空表。
- 学号**固定 4 位**：19班32号填 `1932`，四行、每行 10 个格子，每行只涂一个。名册不是 4 位数字的班级拒绝发布，不自动补位。
- 选项支持 **2–7 个**（A–G），ABC 三选、ABCD 四选、A–G 七选五都有快捷设置。
- 题组标题（听力/阅读/七选五/知识运用）按这份卷子的真实分组印在顶部图例里，并带上真实题号范围。
- 最多 60 题；超过 60 题直接拒绝，不缩格子。
- 试卷二维码 24×24mm，只匹配考试版本，不带学生身份；学号才是唯一身份来源。
- 字母印在格子里会带来中心墨迹，所以识别采样格子**外环**并校验边框，空白格不会被误判成“浅涂”。

排版示例见 [英语卡预览](<preview/english-card-a5-v4.png>)。

## 旧版英语卡（a5-v3，仅兼容）

v0.2.0 曾发布过「每题竖排一列」的 a5-v3 卡。它的坐标已冻结，旧卷仍可正常识别，但新发布的英语卷一律使用上面的 a5-v4。a5-v3 的形态是：

- 学号**固定4位**：19班32号填 `1932`，四行各10个数字格，每行只能涂一个。名册里不是4位数字的班级会被拒绝发布，不自动补位。
- 选项支持 **2–7 个**（A–G），常见组合都有快捷设置：ABC 三选、ABCD 四选、A–G 七选五、T/F 判断。
- 每题一列，选项自上而下竖排；白色方框内印字母。
- 题组标题（例如“第一部分 听力（1–20）”）会按题打印在卡上，同一段里跨题组的会分别标注。
- 一张半A4最多60题。按各段最高选项数计算题行高度；超出可打印高度就**拒绝发布**，绝不把方框缩小到涂不清。
- 试卷二维码缩小到 24×24mm，只用于匹配考试版本，不带学生身份；学号才是唯一身份来源。
- 因为字母印在框内，识别改成采样方框**外环**并校验方框边框，空白框不会被误判成“浅涂”。这一点有专门的回归测试覆盖。

例子：一份 20 题 ABC 听力 + 15 题 ABCD 阅读 + 5 题 A–G 七选五 + 20 题 ABCD 知识运用的 60 题试卷，可以直接在答题卡设置页点“英语60题模板”生成，再改分值和答案。

样板见 [英语卡预览](<preview/english-card-a5-v3.png>)（实际渲染，A4 上下双联）与 [已填涂样例](<preview/english-card-filled.png>)。

## 手机连续扫描

使用Safari/Chrome HTTPS前台相机，一次授权后自动找卡/稳定选帧。完整OMR在独立Web Worker中进行，识别学号、选项和状态；二维码不用于换学生锁。按学号+换卡运动防重复，最多3个本地待提交任务，保留原幂等键。Go根据同一张证据图独立定位、读取学号/答案、查冻结名单与计分；客户端预览不是成绩，只有正式committed才绿灯/成功音。

学号不明/多涂/名单外保存为未绑定待复核，教师可查看原图并显式绑定（需理由和revision）；同学号重复不覆盖，冲突需复核。填错另一个合法学号无法仅凭像素判断，二维码按用户要求不校验学生，所以发卡/填写与班级对账仍然必要。

## VPS开销

标准卡不调用大模型或云端CARD，只有选定单张图在Go做有界图像复核。图像≤4MiB/8MP、并发1，云OCR等待不在默认生产API执行CPU推理。仍需目标2C4G实际测峰值/RSS，不能把容器内存帽说成常态占用。原有a4-v1历史卷保持旧版本/路由，不会把旧纸悄悄解释为新学号卡。

## 验证边界

自动测试覆盖官方协议、模拟图OMR、两学生共用试卷码仍按学号分别入库、PDF页准备/进度/显式恢复、AI确认、重评分、幂等、PostgreSQL重启持久性。浏览器真实执行PDF.js worker、OMR Worker、双联PDF导出与中文渲染，不等于完成所有真实手机与实体2B印刷样本准确率验收。上线试点先打印数张，用真实iPhone/Android、2B/擦除/阴影/透视进行人工双核对照。

## 安装升级

先备份数据库、证据和稳定APP_ENCRYPTION_KEY。通过v0.2.0标签Actions发布两个多架构镜像：

- ghcr.io/alumos/papergrade:0.2.0
- ghcr.io/alumos/papergrade:0.2.0-gateway

是否已实际发布以GitHub Actions结果及GHCR包为准，不以本文的预期名称当作发布成功。

在部署机.env设置IMAGE=ghcr.io/alumos/papergrade:0.2.0，首次必须配置稳定APP_ENCRYPTION_KEY（openssl rand -hex 32），其余OCR/AI地址留后台设置。暂停扫描/等待任务后：

~~~sh
docker compose pull
docker compose run --rm api migrate
docker compose up -d --no-build
~~~

不要down -v，不要更换主密钥。NAS地址不写入Git仓库默认配置；真实测试样图和生成证据仅保存在本机忽略目录。
