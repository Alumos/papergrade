# 用户资源约束（含v0.2修订）

> **v0.2优先规则**：原卷PDF由浏览器分页，NAS/云端Ollama负责OCR，外部AI分析；标准学号卡改为浏览器OMR+Go单图有界复核，不用每卡云模型。以下初版“所有卡都云端识别”已不再是新a5-v2默认。保留低空闲内存、有限并发和无本机模型原则，见 [v0.2说明](<RELEASE_V02.md>)。

用户明确说明：2C4G VPS与其他业务共享，不允许本项目占满，日常入库内存要很低，识别应主要通过云端OCR与AI接口。

因此当前实现默认调整：

| 环节 | 默认位置 |
|---|---|
| 相机视频、稳定检测、择帧压缩 | 手机浏览器 |
| 原卷OCR | 外部OCR网关 |
| 试卷结构理解 | 外部AI接口，草稿需教师确认 |
| 标准卡填涂/二维码识别 | 外部专用答题卡识别网关 |
| 响应格式与名单/版本验证 | Go |
| 规则计分、幂等、成绩与证据 | Go + SQLite 单文件 + 私有文件 |
| 本地OMR | 默认关，仅可选实验 |
| 本地PDF渲染、OCR、LLM | 不在默认镜像或运行路径 |

原设计文档中服务端OMR/逐页PDF Worker与约2.4GiB容器上限是此前备选，不是当前默认部署。新的容器硬帽总计640MiB只是故障保险，不是预留、常态占用或已验收峰值。生产实际空闲RSS需在真实VPS上记录，开发机结果和容器上限都不能代替。

云端识别会有每卡调用成本与学生图像外发边界，不能继续沿用本地OMR“逐卡不调用云服务”的成本假设。需指定供应商并验证协议与识别质量，普通OCR并不自动等于OMR。未配置接口时明确不可用，不制造成功数据。

首期单教师、标准个人卡、40题内单页、有限并发。轻量实现不是完整校级系统，功能差异和待验收清单在项目README记录。
