# First implementation contract

## Latest constraint (supersedes earlier design)

User requires very low actual idle server memory, keeping most VPS resources available for other workloads. Default ALL OCR/card recognition/AI uses external configured gateways; phone selects/ compresses frames. No local PDF renderer/text subprocess or local OCR model. Go handles cloud request orchestration, validation, deterministic scoring, minimal storage. Local vision recognizer is experimental explicitly opt-in only. Low idle connections and adaptive job backoff. Container memory caps are fail-safes, NEVER claims of actual RSS. See docs/CLOUD_PROVIDERS.md and deployment guide. Earlier architecture document has more compute-heavy alternatives, not current defaults.


Project root: papergrade. Go module: github.com/papergrade/papergrade, go 1.24+. Production: PostgreSQL + private filesystem. Development without DATABASE_URL uses explicitly marked in-memory repository (not production safe). SERVER_ADDR default :8080, DATA_DIR default ./data, ADMIN_USERNAME/ADMIN_PASSWORD initial single-teacher account via environment (no hardcoded production credentials). DEV_MODE=true enables insecure localhost cookies only. Go API / Worker command: go run ./cmd/papergrade api|worker|migrate. API and worker same binary/image; frontend is static Vite output. No Docker installed in current host; test through Go / Node, document Docker validation gap.

API base /api/v1. JSON error {code,message,request_id?}. Cookie sessions; same-origin validation for mutations including login, credentialed browser fetch. GET /healthz and /readyz unauthenticated. Everything else except login authenticated. Data is single installation/teacher in first cut (not claim full multi-tenancy). No fake demo data on production. Dev repo starts empty.

Endpoints and shapes (coordinate revisions in this file; never silently change):
- POST /auth/login {username,password} -> {user:{id,username},storage_mode}; POST /auth/logout; GET /me -> same + capabilities.
- GET /classes -> {items:Class[]}; POST /classes {name} -> Class; Class {id,name,student_count,created_at}.
- GET /classes/{id}/students -> {items:Student[]}; POST /classes/{id}/students {students:[{number,name}]} -> {imported}; Student {id,class_id,number,name}. Batch upsert? default reject duplicates and all-or-nothing, preserve leading zeros. Frontend use CSV text input; XLSX later.
- GET /exams -> {items:Exam[]}; POST /exams {title,subject,class_id,questions:Question[]} -> Exam. GET /exams/{id} -> Exam; PATCH /exams/{id} same draft fields with revision. Question {id,number,type:single_choice|multiple_choice|true_false,options:string[],answer:string[],score_units:int,partial_score_units?:int}. Exam {id,title,subject,class_id,status:draft|published,revision,questions,release_id?,template?,created_at,student_count,received_count,review_count}. IDs assigned server. Max questions 40 for initial fixed one-page template (not claim full doc capacity); max options 5. Draft can have no questions; publish requires all valid.
- POST /exams/{id}/publish {revision} -> Exam (freeze immutable release + template). No in-place published edits. Regrade explicit POST /exams/{id}/regrade {revision,answers:[{question_id,answer}],reason}; retain history. Implemented explicit versioned regrade and GET /exams/{id}/grading-history. Release/template unchanged, result histories retained. Also POST /exams/{id}/documents/{docid}/adopt {revision,replace_existing} explicitly imports parsed objective candidates into draft with review_flags/missing values; cannot modify published exams.
- GET /exams/{id}/template -> Manifest (without correct answers). GET /exams/{id}/cards?student_id=... -> SVG printable A4 personal card authenticated; optionally PDF endpoint from vision if feasible. QR payload is opaque sheet token; manifest template contains normalized layout positions plus QR location.
- GET /exams/{id}/sheets -> {items:[{student_id,student_number,student_name,token}]} for authenticated teacher to print; token server-issued random, binds exam release and student. Token not student ID from client.
- POST /exams/{id}/captures multipart form with image (JPEG/PNG), client_capture_id, optional candidate_sheet_token. Require Idempotency-Key same as client_capture_id. <=4MB / <=8MP. Default cloud card gateway independently finds markers/QR and returns validated answers; Go only reads image headers and validates cloud response. LOCAL_OMR_ENABLED=true is explicit experimental opt-in for local full decoding. Unconfigured cloud without local opt-in returns503, not fabricated success. Return 202 {capture_id,status:queued} or committed result below in memory dev synchronous mode. Production queue persisted. GET /captures/{id} -> CaptureResult.
- CaptureResult {capture_id,client_capture_id,status:queued|processing|committed|needs_review|duplicate|conflict|failed,student_display?,submission_id?,score_units?,max_score_units?,review_count?,message?,deduplicated?,answers?:RecognizedAnswer[]}. RecognizedAnswer {question_id,selected:string[],state:answered|blank|invalid_multiple|uncertain,confidence?:number}. Success only committed; duplicate distinct informational state.
- GET /exams/{id}/results -> {items:Result[],summary:{expected,received,needs_review,missing,average_units,max_score_units}}. Result {id,student_id,student_number,student_name,status,score_units,max_score_units,answers,revision,capture_id}.
- GET /exams/{id}/reviews -> {items:Result[]}; POST /results/{id}/review {revision,answers:[{question_id,selected}],reason} -> Result; no client-provided score. Explicit conflict replacement endpoint can be deferred but never overwrite.
- GET /exams/{id}/export.csv -> UTF-8 CSV, prevent formula injection.
- POST /exams/{id}/documents multipart PDF -> {id,status,filename,...}; GET /exams/{id}/documents -> {items}. POST /exams/{id}/parse -> persisted external parser task or 503 PROVIDER_NOT_CONFIGURED (never fabricate extracted questions). GET /settings/capabilities -> {ocr_configured,ai_configured,storage_mode,...} no secrets. Lead implements provider adapter if backend agent leaves scope boundary.

Detect corners server-side and perspective map; QR decoder mature lib. No claim robust arbitrary card. Include synthetic/golden tests with skew, blank, multi-fill, blur/rejection.
